The runtime now uses two fixed local calls: concise decision reading, then compact structured extraction checked against the original transcript. These are measured stages, not automatic retries. Initial two-stage output fixed the active owner/date errors.
- Unresolved tasks duplicating the same cited open question are collapsed into that participant question. Short acceptance/cancellation fragments gain adjacent transcript context, labelled as context, to make bare “Agreed” replies auditable. For an inactive cancelled task only, one explicit cited first-person self-assignment can retain the prior executor when no ownership transfer was reported; ambiguous cases remain null. Unit tests cover these boundaries.
- A 14B backup download was started but cancelled when the two-stage 7B approach worked better. It was not used for inference. The failed 4B weights and the already-extracted installer ZIP were removed to reclaim workspace disk space; all evaluation reports remain.

## Regression failures and grounding fixes

The first full A–E run is preserved in `reports/local-regression-v1/`. A/B had correct final task states, owners and dates, but B's headline retained the old date. C invented an unanswered ownership question even though the speaker had refused ownership. E's small.en transcript dropped Maya's introduction, so the validator correctly withheld the name; another accepted self-commitment was demoted because the model labelled its quote as a proposal. These were failures, not passes.

The runtime removes recognizable trailing dates from action titles, admits only verbatim participant questions, and recognizes explicit unconditional self-commitments independently of evidence-role labels. Small.en was replaced with pinned medium.en; real E audio then restored Maya's name and A restored the word “marketing.”

The next run, preserved in `reports/local-regression-v2/`, exposed stricter-grounding failures: medium.en often omits punctuation/capitalization, while the extraction model reformatted dates and omitted introduction segment references. This incorrectly withheld valid dates and identities. The adapter now finds the exact original date span allowing formatting differences only, and recovers a named speaker's unique self-introduction from that same speaker's actual segments. It never substitutes a different date or guesses an active executor. Ordinary requests such as “Please verify…” are not accepted as questions; duplicate inactive question tasks and no-op changes are removed. The E transcript-only replay after these fixes passed its final fields, but is explicitly not a new audio test.

Final real browser results are in `reports/live/`; F is the unseen post-fix recording. See [quality report](QUALITY-REPORT.md) for final counts and remaining limitations. Acoustic listening has not been performed. Browser playback checks establish seek/stop behavior only.

The decoder now enumerates only actual segment IDs; questions include the following real segment as context; a never-approved proposal cannot carry confirmed-to-proposed history.
