# Architecture and trust boundaries

Browser audio selection → local Web Audio decoding/resampling → 16 kHz mono PCM WAV upload → server byte-level validation → timestamped diarized transcription → concise local decision reading → compact schema-constrained extraction → local schema/evidence validation → browser results and original-audio playback.

The original file is retained as a browser object URL. The converted recording has the same timeline; it is sent as audio bytes. No transcript input UI exists. The server passes bytes through stdin to the local Python speech process and never reads fixtures or expected outcomes. The extraction request receives only system rules and ASR segments, with no upload date or filename.

Runtime: Node 24 built-in modules, plain HTML/CSS/JavaScript and Web Audio; Python speech packages and portable Ollama. No npm runtime packages or frontend build step. Test-only Playwright is provided by the development environment; Windows System.Speech generates fictional synthetic test audio. See `local/requirements.lock.txt` for the installed Python environment.

`faster-whisper-medium.en` estimates word timestamps on CPU with INT8 computation. `pyannote/speaker-diarization-community-1` estimates two exclusive speaker timelines on CPU. Each word is assigned by maximum overlap, and adjacent same-speaker words are grouped into segments. `qwen2.5:7b` in local Ollama reads the full transcript at temperature zero: first as a concise decision reading, then as schema-constrained JSON. Speech and each extraction call have a ten-minute timeout and no automatic retries. Model names, stage durations and language-model token counts are recorded. Downloaded models are reused offline after setup.

The local model selects segment IDs and evidence roles using a compact schema, considers accepted changes before emitting final owner/deadline/status, and identifies introductions. The app expands each selected ID into the full verbatim segment text; the model does not generate quote wording or timestamps. Explicit English month/day/year or ISO dates are normalized with UTC calendar components; relative dates remain unnormalized. The final strict validator derives speaker/start/end from ASR, checks substring matching and time bounds, requires acceptance/cancellation evidence, validates self-introductions, and withholds dates conflicting with change history. This does **not** prove the model interpreted acceptance correctly, or that ASR heard the correct words. Semantic evaluation and listening remain mandatory.

The output schema dynamically enumerates actual segment IDs for every citation, question and introduction reference. A real E run had failed closed on a nonexistent citation; constraining the decoder prevents that identifier from being generated. The validator still checks all references. For open questions the next actual segment is included as context. A never-approved final proposal cannot retain a contradictory history claiming an earlier confirmed status. Model-generated role labels and incomplete histories remain reviewable interpretations, not verified facts.

Missing owner/deadline follow-ups are generated separately as system clarifications. Cancelled and proposed work never appears in the active UI. History carries superseded values. Unverified evidence is withheld and the item is demoted to unresolved. Relative dates without calendar context remain relative.

Participant questions must occur verbatim within a cited segment; an invented question is omitted rather than presented as spoken evidence. Explicit, unconditional first-person commitments can support acceptance even if the extraction model labelled that quote as a proposal. Conditional suggestions do not pass this fallback. Recognizable trailing deadline clauses are removed from task headlines so an old date cannot compete with the final deadline field. These conservative checks address observed errors; semantic labels and change histories still require review.

Two fixed Ollama calls separate interpretation from formatting. The preliminary reading is untrusted intermediate data, checked against the full original transcript in the formatting request, and is not persisted in operational logs. Neither request can read fixture expectations. The compact adapter adds adjacent real context for short agreement/cancellation utterances and removes duplicated unresolved questions. It can retain a cancelled task's prior executor only from one explicit cited self-assignment, with no reported ownership transfer; it never infers a missing active owner this way.

A cited unconditional self-commitment followed by the other speaker's explicit agreement can correct a proposed status to confirmed when selected evidence contains no cancellation or refusal. This narrowly scoped English consistency check was added after F; independent G was recorded and evaluated afterward. The Python speech process reserves a separate JSON output stream before importing dependencies, directing library diagnostics to stderr so warnings cannot corrupt the protocol.

Security and privacy: Hugging Face token only in ignored `.env.local`; no browser token. Downloads contact Hugging Face; audio inference runs on this computer. Ollama uses loopback port 11435 with cloud functionality disabled by the launcher. The active pipeline has no import of the historical OpenAI adapter and no paid fallback. Loopback binding and Host/Origin checks protect the app. Static routes are an explicit allowlist. No transcript/audio is written to disk in normal app operation. Jobs expire from memory 30 minutes after completion or on clear/replacement; audio references end after processing. Timing/usage logs remain locally until manually deleted and contain no audio or transcript. Test scripts explicitly save fictional evaluation results in `reports/`. Browser text is HTML-escaped. Audio and transcript instructions remain untrusted data; prompt safeguards have not been proven against all attacks.

The old OpenAI adapter remains for isolated mocked contract tests and historical comparison. It is not reachable from the active application pipeline.

The inference server remains a local prototype. An optional loopback gateway exposes only allowlisted app routes and fictional audio samples through a public tunnel. It requires a separately generated password, checks origins, caps upload bytes, and restricts each job to its browser session. The tunnel provider terminates HTTPS, so uploaded audio passes through that provider. This temporary demo is not a production multi-user service; see REVIEWER-DEMO.md. No calendar, accounts, payments, task sending or team workspace was added.
